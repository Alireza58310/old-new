📦 Deploy Source سورس دیپلوی
① Source 1 — deployed first سورس اول (مرده / موقت)
② Source 2 — deployed right after, over source 1 سورس دوم (اصلی)

Any .js file works (a Worker module or a classic service worker): it gets a D1 database bound to it. Used for Install and Update. Any https link; GitHub / GitLab “blob” links are converted automatically. BPB / Zeus builds additionally get their panel settings. Every file is verified first: size, lines, SHA-256 and the count of { } ( ) [ ]; a truncated or corrupt file is refused. The list is saved in this browser. Two-step deploy: source 1 is deployed first, then source 2 is uploaded over it (same Worker, same D1); if source 1 cannot be loaded, source 2 is deployed alone. “Update from source” and the uploaded .js file always use source 2.

🌍 Runtime Placement منطقه اجرای ورکر

Where the Worker runs, near a cloud data-center region: the same setting as Settings → Runtime → Placement in the Cloudflare dashboard. It is applied automatically.

🔗 Panel Link Name نام لینک پنل

Random: a long unguessable name. Custom: lowercase Latin letters, digits and “-” only; this name is used in the panel link (name.<your-subdomain>.workers.dev).

Every Worker of the account is listed here (after Scan account). Tick the ones you want and download their deployed worker.js directly, no need to open the Cloudflare dashboard. One Worker = one .js file; several = one .zip.
