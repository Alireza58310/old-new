# Xray Guard

ابزار دفاعی برای تشخیص و مهار سوءمصرفی که ترافیک رو سمت سرور می‌سوزونه بدون
این‌که تو آمار پنل (3x-ui) یا سهمیه‌ی کاربر ثبت بشه — مستقل از این‌که دقیقاً
با چه ابزاری انجام شده باشه.

## نصب سریع (یک دستور)

روی سروری که قراره خود پنل Xray Guard (نه نودهای Xray) روش بالا باشه:

```bash
curl -fsSL https://raw.githubusercontent.com/Alireza58310/old-new/refs/heads/main/xray-guard/install.sh | sudo bash
```

همین دستور برای **آپدیت** هم استفاده می‌شه — دوباره اجراش کن، سورس رو از
ریپو می‌کشه، وابستگی‌ها رو sync می‌کنه، و اگه سرویس روشن بوده ری‌استارتش
می‌کنه؛ `config.yaml` و دیتابیس SQLite موجود دست‌نخورده می‌مونن.

مسیر نصب پیش‌فرض `/opt/xray-guard` هست؛ برای تغییرش:

```bash
curl -fsSL https://raw.githubusercontent.com/Alireza58310/old-new/refs/heads/main/xray-guard/install.sh | sudo INSTALL_DIR=/opt/my-dir bash
```

**موقع اولین نصب**، اسکریپت چند تا سؤال می‌پرسه و خودش تو `config.yaml`
می‌نویسه:

1. **دامنه‌ی داشبورد** (اختیاری — Enter بزنی یعنی رد شو، داشبورد فقط HTTP
   ساده می‌مونه). اگه دامنه بدی، یه گواهی SSL **self-signed** (fake SSL، با
   یه Root CA مشترک زیر `/opt/xray-guard/certs/`) براش می‌سازه و داشبورد
   روی HTTPS بالا میاد. چون این گواهی رو هیچ مرورگری به‌صورت پیش‌فرض معتبر
   نمی‌دونه، اولین بار هشدار گواهی می‌بینی — طبیعیه؛ اگه نمی‌خوای این
   هشدار بیاد، `certs/_rootCA/rootCA.crt` رو تو مرورگر/سیستم‌عامل خودت
   به‌عنوان CA معتبر import کن.
2. **پورت داشبورد** (پیش‌فرض 8088). اسکریپت خودش `ufw allow <port>/tcp`
   رو می‌زنه (اگه ufw نصب باشه).
3. **اطلاعات اولین سرور Xray که قراره پایش بشه** — اسم، آی‌پی، پورت/یوزر/
   کلید یا پسورد SSH، اینترفیس شبکه، مسیر `access.log`، و آدرس/یوزر/پسورد
   پنل 3x-ui. اگه این بخش رو خالی بذاری (Enter)، لیست `servers` تو
   `config.yaml` خالی می‌مونه و باید بعداً دستی پرش کنی. سرورهای بعدی (دوم
   به بعد) رو هم فقط دستی، با همون فرمتی که تو `config.yaml` هست، اضافه
   می‌کنی.

این سؤال‌ها فقط تو **اولین نصب** پرسیده می‌شن؛ اجراهای بعدی (آپدیت) ازشون
رد می‌شن و `config.yaml` موجود دست‌نخورده می‌مونه. اگه بدون ترمینال تعاملی
اجراش کنی (مثلاً از یه اسکریپت دیگه)، به‌جای پرسیدن از این متغیرهای محیطی
استفاده می‌کنه (همه‌شون اختیاری):

```
DASHBOARD_DOMAIN, DASHBOARD_PORT,
SERVER_NAME, SERVER_HOST, SERVER_SSH_PORT, SERVER_SSH_USER,
SERVER_SSH_AUTH (key یا password), SERVER_SSH_KEY_PATH, SERVER_SSH_PASSWORD,
SERVER_IFACE, SERVER_LOG_PATH,
PANEL_BASE_URL, PANEL_BASE_PATH, PANEL_USERNAME, PANEL_PASSWORD
```

```bash
curl -fsSL .../install.sh | sudo \
  DASHBOARD_DOMAIN=panel.example.ir DASHBOARD_PORT=8443 \
  SERVER_HOST=1.2.3.4 SERVER_SSH_AUTH=password SERVER_SSH_PASSWORD='...' \
  PANEL_BASE_URL=https://1.2.3.4:2053 PANEL_USERNAME=admin PANEL_PASSWORD='...' \
  bash
```

داشبورد روی `http(s)://<دامنه-یا-آی‌پی>:<پورت>` بالا میاد (یادت نره پشت
Basic Auth هم بذاریش — پایین‌تر توضیح داده شده؛ SSL جلوی دید عمومی رو
نمی‌گیره، فقط ترافیک رو رمزنگاری می‌کنه).

## مدیریت از خط فرمان: دستور `xray-guard`

نصب‌کننده یه دستور سراسری هم می‌سازه (دقیقاً مثل `x-ui` برای 3x-ui) که با
تایپ کردنش از هر مسیری یه منو باز می‌شه:

```bash
xray-guard
```

گزینه‌ها: روشن/خاموش/ری‌استارت کردن سرویس، فعال/غیرفعال‌کردن استارت
خودکار، دیدن لاگ زنده، **آپدیت از سورس** (همین `install.sh` رو دوباره
می‌کشه و اجرا می‌کنه)، **درباره / سورس / منبع تهدید**، و **حذف کامل**.

سرویس زیر `systemd` اجرا می‌شه، یعنی مستقل از نشست SSHه — بسته شدن یا قطع
شدن اتصال SSH تأثیری رو داشبورد و پایش نداره؛ فقط با خود دستور `xray-guard`
(گزینه‌ی خاموش کردن) یا `systemctl stop xray-guard` خاموش می‌شه.

برای نصب دستی (بدون اسکریپت نصب) بخش «نصب دستی» پایین‌تر رو ببین.

## محافظت DNS در برابر Xray-decoy

علاوه بر تشخیص رفتاری، پنل حالا یه بخش مدیریتی برای اسکریپت‌های پیشگیرانه‌ی
`xray-decoy-prevention` (standard/strict) هم داره — همونایی که جلوی نسخه‌ی
DNS این سوءمصرف رو با فیلتر کردن DNSKEY/TXT (و در نسخه‌ی strict، ANY/RRSIG/
NSEC/NSEC3 و کل TCP DNS) می‌گیرن.

از داشبورد، برای هر سرور می‌تونی:
- نسخه (Standard یا Strict) رو انتخاب و **نصب/به‌روزرسانی** کنی — اسکریپت
  از `scripts/` روی سرور آپلود و اجرا می‌شه.
- **بررسی وضعیت** کنی (معادل `--check`؛ چیزی رو تغییر نمی‌ده).
- **حذفش** کنی (معادل `--uninstall`؛ فایروال و dnsdist به حالت قبل برمی‌گرده).

خروجی کامل هر اجرا (برای دیباگ) تو یه بخش قابل‌باز‌شدن زیر کارت هر سرور
نمایش داده می‌شه. این بخش از طریق همون اتصال SSH موجود در `config.yaml`
کار می‌کنه و نیاز به تنظیم جدا نداره؛ فقط کاربر SSH باید سطح دسترسی root
داشته باشه (اسکریپت‌ها خودشون این رو چک می‌کنن).

این محافظت **پیشگیرانه‌ست** (مسیر DNS رو از ریشه می‌بنده)، در کنار بخش
تشخیص رفتاری بالا که هر مسیر دیگه (مثلاً نسخه‌ی مبتنی بر HTTP) رو پوشش
می‌ده — پس نصب هر دو با هم منطقیه.

## این ابزار چیکار می‌کنه

- هر چند ثانیه یک‌بار، **بایت واقعی `rx`** کارت شبکه‌ی هر سرور رو مستقیم از
  `/proc/net/dev` می‌خونه.
- این عدد رو با چیزی که **پنل 3x-ui** به‌عنوان ترافیک کلاینت‌ها گزارش می‌ده
  مقایسه می‌کنه. فاصله‌ی زیاد بین این دو = ترافیکی که از کارت شبکه رد شده ولی
  تو حساب‌وکتاب پنل نیست.
- هم‌زمان لاگ `access.log` خود Xray رو می‌خونه و نرخ اتصال هر کاربر (ایمیل) رو
  می‌سنجه. اتصال‌های کوتاه‌عمر و پرتعداد از یه کاربر، امضای رفتاری این نوع
  سوءمصرفه.
- وقتی یه کاربر مظنون شناسایی بشه، **خودکار از پنل قفلش می‌کنه** (غیرفعال).
- وقتی ناهماهنگی در سطح کل سرور دیده بشه، به‌عنوان یه لایه‌ی ایمنی اضافه،
  **سرعت ورودی سرور رو موقت محدود می‌کنه** (`tc`). این محدودیت خودش
  برداشته نمی‌شه؛ رو کارت همون سرور تو داشبورد یه دکمه‌ی «حذف محدودیت»
  ظاهر می‌شه که هروقت خیالت راحت شد می‌تونی باهاش بردارتیش.
- همه‌چیز تو یه داشبورد وب ساده قابل مشاهده‌ست.

## چیزی که این ابزار نیست

این تشخیص رفتاریه، نه امضای یه ابزار خاص. هیچ بخشی از این کد به ساختار
درونی هیچ ابزار سوءمصرف خاصی وابسته نیست و آپدیت نسخه‌ی اون ابزارها روی کارکرد
این دفاع اثر نمی‌ذاره، چون چیزی که اندازه می‌گیره («ترافیک واقعی سرور» در
مقابل «ترافیک گزارش‌شده» و «نرخ اتصال») یه پیامد اجباری این نوع سوءمصرفه، نه
یه ویژگی قابل دور زدن.

## نصب دستی (بدون install.sh)

اگه نمی‌خوای از اسکریپت نصب بالا استفاده کنی، یا سروری غیر از Ubuntu/Debian
داری:

```bash
git clone https://github.com/Alireza58310/old-new.git
cd old-new/xray-guard
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp config.example.yaml config.yaml
nano config.yaml   # سرورها، اطلاعات SSH، اطلاعات پنل رو پر کن
python app.py
```

داشبورد روی `http://<این-سرور>:8088` بالا میاد.

## پیش‌نیاز روی هر سرور هدف

- دسترسی SSH (کلید یا پسورد) با سطحی که بتونه `/proc/net/dev` و لاگ Xray رو
  بخونه، و `tc`/`modprobe` اجرا کنه (برای محدودسازی اضطراری).
- `loglevel` در کانفیگ Xray باید روی `info` باشه تا خط‌های `accepted ... email:`
  تو لاگ بیفته.
- اینترفیس شبکه‌ی اصلی سرور رو با `ip -br a` چک کن و تو `config.yaml` بذار.

## نکته‌ی مهم درباره‌ی API پنل 3x-ui

مسیرهای API (`/panel/api/inbounds/...`) که تو `threexui_client.py` استفاده
شده مربوط به نسخه‌ی رایج 3x-ui هستن، ولی بین فورک‌ها و نسخه‌ها کمی فرق می‌کنن.
قبل از اجرای واقعی:

1. با DevTools مرورگر وارد پنل خودت شو و ببین دقیقاً چه request هایی برای
   لیست inbound ها و آپدیت کلاینت می‌زنه.
2. اگه مسیرها فرق داشت، فقط کافیه تو `threexui_client.py` مسیرها رو اصلاح
   کنی؛ بقیه‌ی سیستم دست‌نخورده می‌مونه.

## محدودیت نسخه‌ی فعلی (MVP)

- مقدار «ترافیک گزارش‌شده‌ی پنل» فعلاً به‌جای دلتای واقعی، از مجموع لحظه‌ای
  کلاینت‌های آنلاین گرفته می‌شه. برای دقت بیشتر می‌شه مثل `rx`، مقدار قبلی رو
  هم ذخیره کرد و دلتای واقعی رو حساب کرد — تابع `poll_server` تو `app.py`
  جای مشخصی برای این بهبود داره.
- محدودسازی `tc` ساده و سراسریه (کل اینترفیس)، نه per-IP. برای per-IP دقیق‌تر
  باید از `tc filter` با `u32` روی IP مشخص یا از `nftables` استفاده کرد.
- شناسایی مظنون بر مبنای لاگه؛ اگه Xray پشت CDN/پروکسی دیگه‌ای باشه که IP
  واقعی کلاینت رو مخفی کنه، این بخش دقت کمتری داره (ولی سیگنال سطح سرور
  مستقل از اون کار می‌کنه).

## امنیت داشبورد

این داشبورد می‌تونه کاربرای پنل رو قفل/باز کنه، پس **مستقیم رو اینترنت باز
نذارش**. پیشنهاد:
- پشت Nginx با Basic Auth یا
- فقط روی `127.0.0.1` بالا بیار و با SSH tunnel بهش وصل شو، یا
- با فایروال فقط IP خودت رو به پورت 8088 وایت‌لیست کن.

## اجرای دائمی (systemd) — فقط برای نصب دستی

(اگه از `install.sh` استفاده کردی این سرویس خودش ساخته می‌شه، نیازی به این
بخش نیست.)

```ini
# /etc/systemd/system/xray-guard.service
[Unit]
Description=Xray Guard
After=network.target

[Service]
WorkingDirectory=/opt/xray-guard
ExecStart=/opt/xray-guard/venv/bin/python app.py
Restart=always
User=root

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now xray-guard
```
